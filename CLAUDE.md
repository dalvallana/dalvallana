# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

A personal blog, meant to grow into a larger app, built on TanStack Start. It is client-first (data goes through TanStack Query) but SSR-rendered, with static pages prerendered. Bun is the package manager; Node 24 (`.nvmrc`) is the runtime for dev, tests and builds.

## Commands

```bash
bun run dev            # Vite dev server on :3000
bun run build          # production build; also prerenders static pages (starts an internal preview server)
bun run preview        # serve the build with srvx on :4173 (static files from dist/client, SSR from dist/server/server.js)
bun run test           # Vitest: `unit` project (node, src/**/*.test.ts) + `browser` project (Chromium, src/**/*.test.tsx)
bun run test:e2e       # Playwright: builds, starts preview on 127.0.0.1:4173, runs e2e/ (incl. axe a11y checks)
bun run lint           # Oxlint (type-aware via .oxlintrc.json)
bun run format         # Oxfmt (write); format:check to verify
bun run typecheck      # tsc --noEmit (TypeScript 7, the native compiler)
```

Single tests:

```bash
bunx vitest run --project unit src/content/select.test.ts
bunx vitest run --project browser src/components/theme-toggle.test.tsx
bunx vitest run -t 'flips between'            # by test name
bunx playwright test e2e/site.spec.ts -g '404'
```

- Lefthook's pre-commit hook runs format (on staged files, re-stages fixes), lint (staged `.ts`/`.tsx`) and the whole-project typecheck. CI (`.github/workflows/test.yml`) runs only `bun run test` and `bun run test:e2e`. Lint, format and types are enforced by the hook alone.
- `typecheck` needs `.content-collections/generated` (gitignored), so on a fresh clone run `bun run dev` or `bun run build` once first.
- `src/routeTree.gen.ts` is generated by the Start plugin and committed. Don't edit it by hand.
- Installing packages: the shell may export `NPM_CONFIG_REGISTRY` pointing at an internal mirror, which overrides `bunfig.toml`. Prefix installs with `NPM_CONFIG_REGISTRY=https://registry.npmjs.org/`, then check that `grep -c npm.apple.com bun.lock` is 0. CI can only reach the public registry.
- `bunfig.toml` sets `minimumReleaseAge` to 3 days, so Bun won't resolve versions newer than that. To take a vetted fresh release early, add an exact `name@version` to `minimumReleaseAgeExcludes` rather than lowering the window.
- Claude Code sandbox: commands that open a port (dev, preview, build, Vitest browser mode, Playwright) only work when run as the exact allowlisted strings: `bun run dev`, `bun run preview`, `bun run build`, `bun run test`, `bun run test:e2e`, `bunx vitest run --project browser`. Run them alone, with no pipes or extra args; start servers as background processes. Subagents don't get the allowlist, so run these yourself.

## Architecture

**Routing and locales.** File routes live under `src/routes/{-$locale}/` (an optional path segment). English has no prefix; Spanish is `/es/...`.

- `src/routes/{-$locale}/route.tsx` is the layout. Its `beforeLoad` validates the segment with `parseLocale`, throws `notFound()` for unknown values (the optional segment otherwise matches any first path segment), 301-redirects `/en/...` to the unprefixed URL, and puts `locale` into the route context. Child routes read `locale` from context, not from params.
- To link with a locale, pass `params={{ locale: localeParam(locale) }}`, which is `undefined` for English.
- UI strings live in `src/lib/messages.ts` (a plain object per locale; no i18n library yet).

**Content pipeline (two halves joined by the file path).**

1. `content-collections.ts` reads only the frontmatter (`parser: 'frontmatter-only'`) of `content/posts/<locale>/<slug>.mdx`, validates it with Zod, and adds `locale`, `slug` and `filePath`. Code imports the result as `allPosts` from `content-collections`.
2. MDX bodies are compiled by `@mdx-js/rollup` in Vite (frontmatter stripped by `remark-frontmatter`). `src/content/mdx.ts` loads them per post via `import.meta.glob`.
   - Loaders `await preloadPostBody(filePath)` so `getPostBody` returns the component synchronously. SSR and prerendered HTML therefore contain the body inline; it would otherwise stream as a hidden Suspense segment.
   - Don't use `@content-collections/mdx`: it evaluates code with `new Function`, which Cloudflare Workers (a likely deploy target) forbid.

- Shared post components (available in MDX without importing) are registered in `src/components/mdx/mdx-components.tsx`.
- Posts with `draft: true` are visible only in dev. `selectPosts`/`selectPost` filter the metadata, and `vite/exclude-drafts.ts` empties draft sources in production builds so no draft text reaches any chunk.

**Data flow (the source boundary).**

- `src/content/posts.ts` holds the Start server functions `getPosts`/`getPost` (`createServerFn().validator(zod)`). They are the only code that touches `allPosts`, and a future CMS or database replaces this file.
- The selection logic lives in `src/content/select.ts` as pure functions: locale fallback (a Spanish request falls back to the English post with `fallback: true`), draft filtering and ordering.
- `src/queries/posts.ts` holds the `queryOptions` factories (`staleTime: 'static'`, since content only changes on deploy). Loaders call `queryClient.query(...)`; `ensureQueryData` is deprecated. Components call `useSuspenseQuery` with the same options.
- `src/router.tsx` creates a fresh `QueryClient` per router and wires `setupRouterSsrQueryIntegration`.

**Rendering.** `vite.config.ts` prerenders `/`, `/es`, `/posts` and `/es/posts` and crawls their links to find posts. Everything else (404s, untranslated fallbacks, `/en` redirects) is SSR.

- `preview.host` is pinned to `127.0.0.1` because prerendering fetches from Vite's preview server, and `localhost` broke on GitHub's Ubuntu runners.
- App code under `src/` must not import Node built-ins (enforced by a `no-restricted-imports` override in `.oxlintrc.json`); build-time config may.

**Theming.** `<html data-theme="light|dark|system">` drives everything; there is no `.dark` class.

- Colors in `src/styles/app.css` are single `light-dark()` values, and `color-scheme` picks the side. The Tailwind `dark:` variant is a block `@custom-variant` covering `dark` and `system` under `prefers-color-scheme: dark`, so system mode needs no JS.
- The `theme` cookie is written in the browser (`persistTheme`) and read by `getTheme` (`createIsomorphicFn` in `src/lib/theme-env.ts`) in the root `beforeLoad` for SSR pages.
- Prerendered pages are built as `system`, and a `ScriptOnce` script in `__root.tsx` applies the cookie before first paint.
- The cookie only ever holds `light` or `dark`: `system` is the default, and the toggle flips what is on screen. Its sun/moon icons follow `data-theme` through `dark:`, so it renders the same on the server and needs no `ClientOnly`; it reads the cookie only when pressed.
- `theme-toggle.tsx` must stay free of `theme-env` imports so its browser test never pulls in `@tanstack/react-start/server`.

**UI.** shadcn uses the React Aria base (`components.json` style `aria-nova`; add components with `bunx shadcn add <name>`). Components use React Aria props (`onPress`, not `onClick`), and `cn` comes from the `cn` package. Once added, components are ours to edit to satisfy lint rules.

- Always build UI from shadcn components when one fits (`bunx shadcn add <name>`, then compose it); don't hand-roll a widget on raw `react-aria-components` that shadcn already provides. If the registry (`ui.shadcn.com`) is unreachable, stop and say so instead of working around it.

## Conventions and lint quirks

- Formatting: tabs, single quotes, no semicolons, 120 columns. Imports and Tailwind classes are sorted by Oxfmt.
- Spacing: no margins between elements (`mt-*`, `mb-*`, `space-y-*`, ...). Make the parent a flex container and use `gap-*`; group siblings in a wrapper when they need different gaps. Prefer flex; use grid only for genuinely two-dimensional or more customized layouts. Two exceptions remain: `mx-auto` to center a column, and vertical margins on MDX components, which sit in `prose` flow that is spaced with margins.
- The Oxlint config is a migration of the user's Biome rules; fix code rather than disabling rules. Rules that commonly bite:
  - `unicorn/no-useless-undefined`: no explicit `undefined` arguments; use optional params or `null` in tests.
  - `unicorn/no-array-sort`: use `toSorted` (which is why tsconfig `lib` is ES2023).
  - `typescript/no-unnecessary-condition`: type-aware; widen types honestly instead of adding casts.
  - `typescript/consistent-type-definitions`: use `type`, except for module augmentation (see the disable comment in `src/router.tsx`).
  - `vitest/require-mock-type-parameters`: write `vi.fn<(x: T) => void>()`.
  - `typescript/no-deprecated`.
- `tsconfig.json` belongs to the user. It uses `erasableSyntaxOnly` (no enums, namespaces or parameter properties). Ask before changing it.
- Vitest APIs are imported explicitly (no globals). `vitest-browser-react`'s `render` is async and returns locators; assert with `expect.element(...)`.
- Brainstorming specs, design docs and implementation plans must not be committed to this repo.
