# Blog Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a working TanStack Start blog skeleton: MDX posts in `en` and `es`, light, dark and system themes, the agreed toolchain (Oxlint, Oxfmt, tsgo, Lefthook), and passing Vitest and Playwright suites.

**Architecture:** TanStack Start (Vite 8) runs on Node, and Bun is the package manager. content-collections validates post frontmatter only. MDX bodies are compiled by `@mdx-js/rollup` and loaded lazily per post through `import.meta.glob`. Route loaders fill the TanStack Query cache by calling server functions, so the data source can change later without touching routes. Static pages are prerendered by crawling links; everything else is SSR.

**Tech Stack:** Bun 1.3, Node 24 LTS, TanStack Start/Router 1.16x, TanStack Query 5, React 19, Vite 8, content-collections, MDX 3, Tailwind v4, shadcn (`aria-nova` style), react-aria-components, Zod 4, TypeScript 7, Vitest 5 (browser mode + Playwright provider), Playwright 1.64, axe, Oxlint, Oxfmt, Lefthook, GitHub Actions, Dependabot.

**Spec:** `docs/superpowers/specs/2026-10-16-blog-scaffold-design.md`

## Where this plan departs from the spec

Each departure comes from API research. Task 15 updates the spec to match.

1. **Theme switching runs on the client.**
   - The spec had a server function that sets the cookie, followed by `router.invalidate()`. That breaks on prerendered pages, which are rendered without a cookie.
   - Instead:
     - The toggle writes the `theme` cookie and `<html data-theme>` directly in the browser.
     - The server reads the cookie when it renders SSR pages.
     - A tiny `ScriptOnce` script applies the cookie on prerendered pages before first paint.
     - The toggle renders inside `<ClientOnly>`, so its label never mismatches during hydration.
   - Dark colors come from `light-dark()` plus `color-scheme`. `system` mode needs no JavaScript.
2. **The theme is a `data-theme` attribute, not a `.dark` class.** That lets one CSS variant cover `dark` and `system`.
3. **Prerendering crawls links** from `/`, `/es`, `/posts` and `/es/posts`. The config file doesn't read the filesystem.
4. **A fourth tsconfig addition: `"node"` in `types`.**
   - Config files (`playwright.config.ts`) need `process`.
   - The "no Node APIs in app code" rule is enforced by an Oxlint `no-restricted-imports` override on `src/**` instead.
5. **No Playwright browser cache in CI.** Playwright's CI guide advises against caching browsers.
6. **Server functions use `.validator()`.** `.inputValidator()` was removed in Start 1.169.

## Prerequisites (user)

- **The project uses the public npm registry.** `bunfig.toml` pins `registry.npmjs.org`, overriding the user-level `.npmrc` for this repo.
- **The user installs all dependencies up front.** The agent sandbox can't reach package registries. Every **Install** step in this plan is therefore _verify only_: run `bun pm ls 2>/dev/null | grep -E '<pkg>'` for the listed packages. If one is missing, stop and ask the user to install it; never try `bun add` yourself.
- **Network-only commands are run by the user.** These are `bunx playwright install chromium` (done up front) and `bunx shadcn add button` (Task 5; the agent pauses and asks).
- **Lefthook's postinstall may already have installed a git hook.** If `.git/hooks/pre-commit` exists before Task 3, run `bunx lefthook uninstall` during Task 1. Task 3 installs it properly.

```tsx
export function getRouter() {

		scrollRestoration: true,
```

- [ ] **Step 6: Implement `src/lib/i18n.ts`**

```ts
export const locales = ['en', 'es'] as const
export type Locale = (typeof locales)[number]
export const defaultLocale: Locale = 'en'

export function isLocale(value: unknown): value is Locale {
	return locales.some((locale) => locale === value)
}

/** Maps the optional `{-$locale}` URL segment to a locale; `null` means the segment is not a locale. */
export function parseLocale(param: string | undefined): Locale | null {
	if (param === undefined) return defaultLocale
	return isLocale(param) ? param : null
}

/** The value for the `{-$locale}` segment when linking: the default locale has no prefix. */
export function localeParam(locale: Locale): Locale | undefined {
	return locale === defaultLocale ? undefined : locale
}
```

```ts
import { z } from 'zod'

export const themes = ['light', 'dark', 'system'] as const
export type Theme = (typeof themes)[number]
export const themeCookieName = 'theme'

const themeSchema = z.enum(themes)

export function parseTheme(value: unknown): Theme {
	const result = themeSchema.safeParse(value)
	return result.success ? result.data : 'system'
}

export function nextTheme(theme: Theme): Theme {
	return themes[(themes.indexOf(theme) + 1) % themes.length]
}

export function readThemeCookie(cookies: string): Theme {
	const match = new RegExp(`(?:^|;\\s*)${themeCookieName}=([^;]*)`).exec(cookies)
	return parseTheme(match?.[1])
}

/**
 * Runs before first paint. Prerendered pages are built without a cookie, so this applies the
 * visitor's saved theme; on SSR pages it re-applies what the server already rendered.
 */
export const themeScript = `document.documentElement.dataset.theme=(document.cookie.match(/(?:^|;\\s*)${themeCookieName}=(light|dark|system)/)||[])[1]||'system'`
```

```ts
import { createIsomorphicFn } from '@tanstack/react-start'
import { getCookie } from '@tanstack/react-start/server'

import { parseTheme, readThemeCookie, type Theme, themeCookieName } from '@/lib/theme'

/** The visitor's theme: from the request cookie on the server, from `document.cookie` in the browser. */
export const getTheme = createIsomorphicFn()
	.server((): Theme => parseTheme(getCookie(themeCookieName)))
	.client((): Theme => readThemeCookie(document.cookie))

/** Saves the choice for future requests and applies it immediately. Browser only. */
export function persistTheme(theme: Theme) {
	document.cookie = `${themeCookieName}=${theme}; path=/; max-age=31536000; samesite=lax`
	document.documentElement.dataset.theme = theme
}
```

```ts
import { defaultLocale, type Locale } from '@/lib/i18n'

export type PostMeta = {
	locale: Locale
	slug: string
	title: string
	description: string
	date: string
	draft: boolean
	tags: string[]
	filePath: string
}

export type PostResult = { post: PostMeta; fallback: boolean }

type SelectOptions = { includeDrafts: boolean }

export function selectPosts(posts: readonly PostMeta[], locale: Locale, { includeDrafts }: SelectOptions) {
	return posts
		.filter((post) => post.locale === locale && (includeDrafts || !post.draft))
		.sort((a, b) => b.date.localeCompare(a.date))
}

export function selectPost(
	posts: readonly PostMeta[],
	locale: Locale,
	slug: string,
	{ includeDrafts }: SelectOptions,
): PostResult | null {
	const matches = (post: PostMeta, inLocale: Locale) =>
		post.locale === inLocale && post.slug === slug && (includeDrafts || !post.draft)

	const exact = posts.find((post) => matches(post, locale))
	if (exact) return { post: exact, fallback: false }
	if (locale === defaultLocale) return null

	const fallback = posts.find((post) => matches(post, defaultLocale))
	return fallback ? { post: fallback, fallback: true } : null
}
```

```ts
import { notFound } from '@tanstack/react-router'
import type { MDXContent, MDXModule } from 'mdx/types'
import { type LazyExoticComponent, lazy } from 'react'

// One lazy chunk per post; keys look like `/content/posts/en/hello-world.mdx`.
const modules = import.meta.glob<MDXModule>('/content/posts/**/*.mdx')
const bodies = new Map<string, LazyExoticComponent<MDXContent>>()

function moduleLoader(filePath: string) {
	const load: (() => Promise<MDXModule>) | undefined = modules[`/content/posts/${filePath}`]
	if (!load) throw notFound()
	return load
}

/** Starts loading a post body so rendering doesn't wait for the chunk. */
export function preloadPostBody(filePath: string) {
	return moduleLoader(filePath)()
}

/** A stable lazy component per post, safe to call during render. */
export function getPostBody(filePath: string) {
	let body = bodies.get(filePath)
	if (!body) {
		body = lazy(moduleLoader(filePath))
		bodies.set(filePath, body)
	}
	return body
}
```
